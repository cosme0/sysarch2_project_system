5Key Relationships

  • Sale → SaleItem — one sale has many line items; a line item belongs to exactly one sale.
  • Sale → DispenseBatch — every sale carries one batch_ref, generated by newBatchRef(), which groups the physical doses for that order.
  • DispenseBatch → DispenseHistory — one batch produces many history rows, one per channel actually released.
  • Medication → StockMovement — every stock change (restock, dispense, adjustment) is an immutable movement row, so on-hand stock is auditable.
  • SerialBridge ↔ DispenserController — the Node bridge speaks the serial protocol (DISPENSE, RELEASE, STOCK, SYNC, STATUS, BUZZ, READY); the firmware dispenses per channel and answers with lights and buzzes.
  • DispenseSimulator → SerialBridge — when the bridge is unreachable, ALLOW_OFFLINE_SIMULATION substitutes the simulated result so a sale still completes.
  • User → AuditLog — each guarded action writes an activity row attributed to the signed-in user.
